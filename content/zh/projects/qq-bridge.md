## 项目定位

想在 QQ 群里养一个「活的」AI:它有固定人格、记得聊过什么、知道什么时候该接话什么时候该潜水,而不是一个随叫随到的问答机器人。qq-bridge 做的事就是把 QQ 消息桥接进本地运行的 DeepSeek Harness(DSH)持久会话,再把 AI 的回复发回 QQ——双向、常驻、低延迟。

## 项目来历

纯原创项目,从第零行开始写,当前版本 v0.2.1-r1。起因是现有的 QQ 机器人框架都在「命令式交互」里打转,而想要的是仿真群友:会抢话、会装死、会斗图。DSH 提供会话与工具能力,SnowLuma 提供 OneBot v11 网关,中间这层调度、安全与状态管理就是本项目。

## 主要功能

- 二代仿真模式(reserved2):唤醒调度器按 @/名字/关键词/提问/拍一拍/概率等条件叫醒 AI,支持合批窗口与限频(每分钟/每小时唤醒配额),AI 通过 MCP 工具自行决定接话或收尾
- 真人感发送:按数组分条、随机条间间隔、长间隔概率、单条字数上限,发送限额按分钟/小时硬约束
- 多模态:图片/表情/动图(抽帧拼图)/语音(ffmpeg 音量归一)/合并转发的读取与发送
- 群聊黑话学习:自动提取候选词,联网考究后写入注入提示词的黑话表,控制台人工确认
- 长期记忆:按人一本账 + 跨会话聊天流水,私聊群聊认得同一个人
- 费用护栏:按 token 账本折算计费,日预算软上限 + 0 点日切恢复 + 管理员日报
- 安全边界:会话级令牌 + 常数时间比较、发送内容敏感信息审计与脱敏、双闸防令牌泄露、state 目录 ACL 收紧(Windows icacls)、preset 校验失败拒绝建会话(fail-closed)
- 长跑韧性:DSH/SnowLuma 断线消息入队补投、损坏状态文件 .corrupt 隔离 + 只读降级、token 自愈、5 分钟心跳与运行态快照

## 技术栈

Node.js(ESM,>=22.13)/ SnowLuma SDK(OneBot v11 over WebSocket)/ DSH 2.0.18 Web API(Cookie 鉴权 + remote.mux 事件流)/ MCP stdio 服务(zod 参数校验,三个:消息、网关状态、安全联网搜索)/ 45 个离线回归脚本组成的 test:audit 套件

## 制作过程

最难的不是收发消息,而是「状态」:唤醒调度、未读水位、潜水定时器、发送队列散落在几万行里,任何一处漏清都会变成静默故障。后来所有撤销路径收敛到统一的清理函数,状态文件统一走「读坏即隔离、绝不回写」的口径。第二个坑是安全:群聊内容是不可信输入,AI 的发送工具必须按会话令牌授权、出站文本必须审计,否则一个 prompt injection 就能让机器人把本地路径发到群里。最后补了一轮 24~72 小时长跑验收:每小时采样内存/句柄/队列,注入故障(杀进程、占端口、损坏状态文件),全绿后才敢挂上去不管。
