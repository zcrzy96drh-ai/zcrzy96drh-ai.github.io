「你按下发送键的这一秒，这条消息要横跨半个地球。」这是短片的开篇字幕。

选题指向一个每天发生、却很少被完整观察的过程：一条消息从手机发出，依次经过基站、光纤、DNS、路由表与海底光缆，最终在另一个大陆落地。全片拆为九幕，成片 2 分 54 秒、3840×2160，画面、字幕、配音、音乐与音效均由代码生成。

> **制作：DeepSeek Harness（DSH）+ DeepSeek v4.1 Flash**
>
> **规格：3840×2160 / 30fps / 2 分 54 秒 / 5223 帧**
>
> 全部代码、文案、配音、混音、渲染与验收由 DSH + DeepSeek v4.1 Flash 完成；本人负责选题、验收标准制定与最终审核。

本文按制作顺序记录关键决策与验证方法，第 9 节汇总成片规格与交付信息。

## 1. 先确立数据，再进入视觉

该选题的难点在于数据密度：99%、600 多条、150 万公里、996,000 条路由、1 毫秒、46 毫秒、每年 150–200 次故障。任一数据有误，都会影响全片可信度。

因此第一步并非撰写文案，而是建立**事实清单**：共 22 条，每条记录三项内容——片中的表述、出处原文、所做的简化。该清单暴露了三个关键问题：

- **同一机构存在多种口径**：ITU 一处写「approximately 99%」，另一处写「estimated 95%」，另有「99%–99.9%」的区间表述。片内统一采用「约 99%」，并在字幕脚注注明来源。
- **0.37% 并非全球占比**：FCC 的统计口径为「卫星占美国国际容量 0.37%」。若片中仅写「卫星只占 0.37%」，即等同于将美国口径替换为全球口径。
- **150–250 毫秒缺乏权威统计**：该区间为跨太平洋链路的工程经验值。片内与清单均标注为「经验区间」，并说明其非权威统计。

在成片中，凡引用数据均附带来源注记；凡示意图均标注「非等比」「表项为示意」；地图上的光缆路径为两点间大圆示意，并非真实海缆路由。上述边界均直接呈现在画面上，而非仅记录于文稿。

## 2. 技术选型：Remotion + d3-geo + NumPy

- **画面**：Remotion，以 React 组件作为帧。直接输出 4K H.264，无需先生成 PNG 序列；修改任一数值后重新渲染即可。
- **地图**：`d3-geo` 与 `world-atlas` 的 Natural Earth 110m 数据，大圆航线通过 `geoInterpolate` 采样。实现要点：默认投影会将跨太平洋弧线切断，需将投影中心设为 170°E，上海至北美西海岸才呈现为连续曲线。
- **音乐与音效**：NumPy 合成。和弦垫、琶音、低频脉冲、踩镲、whoosh 与声呐均由正弦波、噪声与包络生成，未使用任何采样文件。
- **配音**：`edge-tts`，音色 `zh-CN-XiaoxiaoNeural`。中文自然度可满足解说需求，并可获取句级时间戳。
- **校验**：`ffprobe` 与 `ffmpeg`。全部验收项均以命令形式固化，避免依赖主观判断。

## 3. 以音频驱动时间轴

此前的项目（[98 秒 DeepSeek 自述片](/projects/deepseek-film/)）采用「先排画面、后配旁白」的流程，导致字幕与语音大面积错位，最终只能通过变速补救。本片将流程反转，**由音频决定时间轴**：

1. 文案拆分为 29 条字幕，再将相邻的 1–3 句合为 17 个「句组」，每组单独送 TTS 合成；
2. 启用 `SentenceBoundary` 事件，直接获取每句的起止时间；
3. 场景时长 = 前导 + 各组时长 + 组间停顿 + 收尾，向上取整至 30fps 的整帧；
4. 输出一份 `timeline.json`，记录场景起止帧与每条字幕的绝对时间。

后续所有环节均读取该文件：字幕出现、数据卡浮入、标记绘制与音效落点，均来自同一组时间数据，因此不存在累积误差。

另一个容易忽略的实现细节是场景起点必须**对齐帧边界**（累计 `durFrames / 30`），音频亦按同一帧边界铺设。据此，场景级音画偏移恒为 0 帧；对交付文件音轨与配音母版做全局互相关，实测偏移 **+0.0 ms**。

## 4. 配音：从朗读式合成到口语化表达

第一版配音的问题集中在三点：语速偏慢、语调平坦、听感接近朗读。原因在于逐句独立合成、全片统一语速，且句间停顿等长。

调整集中在三个方面：

- **句组合成**：同一组的 2–3 句连续送入 TTS，句间停顿交由模型处理，避免逐句拼接造成的断裂感。
- **组级语速与音高**：开场 +26% / +4Hz（推进感）、海底 −4% / −4Hz（空间感）、结尾 −10% / −5Hz（收束感），共 17 组参数。
- **文本节奏**：引入破折号停顿、短句与设问，将重音落在数字上。

更关键的一步，是将主观听感转化为可断言的指标。生成脚本内置两条硬性检查，不满足则构建失败：

```python
assert np.std(rates) > 0.25   # 语速标准差：避免匀速朗读
assert f0_sd > 15             # 基频标准差：避免语调平坦
```

最终指标：语速 4.57 字/秒（标准差 0.32，区间 4.01–5.25），基频标准差 52.8 Hz，音高 p10–p90 跨度 139 Hz。

## 5. 代价最高的问题：立体声未降混

更换配音并完成首版渲染后，成片听感明显异常：人声近似放慢一倍，且越到后段与画面偏离越大。

排查并未依赖反复试听，而是先测量基频：均值 **123 Hz**。女声正常音区约 240 Hz，二者恰好呈二倍关系，指向**两倍时间拉伸**。

沿此线索检查音频拼接代码，问题定位明确：

```python
# 场景音频写成立体声
write_wav(path, np.stack([buf, buf], axis=1))

# 读取时未降混
x = np.frombuffer(w.readframes(n), dtype=np.int16)
buf[i0:i1] += x[: i1 - i0]     # 立体声帧被当作两个单声道样本 → 时长 ×2
```

每个立体声帧（L、R 两个采样）被当作两个连续的单声道采样写入，音频长度翻倍，并与下一场景重叠，表现为听感上的慢速与音画错位。

修复仅需一行——读取时降混：

```python
if ch == 2:
    x = x.reshape(-1, 2).mean(1)
```

更重要的是增加断言。当前每次构建均检查：首个发声点必须落在首条字幕 ±80 毫秒内。若该断言在早期版本中已存在，问题版本不会被交付。

修复后指标：基频回到 **236.8 Hz**，全片由 191.8 秒缩短至 **174.1 秒**，同时将整体语速提高 10 个百分点。

## 6. 重点标记：突出数字且不遮挡字幕

观众对长句的记忆有限，对数字更敏感。片中因此设置四类标记：

| 类型 | 数量 | 例子 |
|---|---|---|
| 关键词色块高亮 | 15 处 | 「发送键」「唯一一段无线」「一百万条」 |
| 手绘式圈选 | 5 处 | 1 ms、200,000、996,000、99、46 |
| 下划线 | 3 处 | IPv4 地址、150 万、150–200 |
| 色块衬底 | 1 处 | 150–250 ms |

实现由三个组件构成：`Circled`（两层 SVG 椭圆，刻意偏移数度以接近手绘效果）、`Underlined`、`HighlightBlock`。绘制动画统一采用 `pathLength=1` 配合 `strokeDashoffset`，或以 `scaleX` 从左向右展开。

两条硬性约束：

1. **标记层始终位于字幕层之下**，字幕始终为画面最上层；
2. 字幕基线上方 240px 范围内不放置任何标记。标注数量可以减少，但不得覆盖字幕。

实现中遇到的问题：下划线会被下方说明文字遮挡，通过为标记容器增加下边距解决；圈选组件置于 flex 布局时会撑开行高，需在外层包裹 `inline-block`。

## 7. 三个片尾版本：正片仅渲染一次

成片需按版权主体拆分为三个版本，片尾仅显示对应名称，不出现平台名称。

若整片渲染三次，等同于将 169 秒正片重复编码三次。采用的方案是拆分渲染：

1. 正片渲染一次（`Body`，5073 帧，不含落款页）；
2. 落款页单独渲染三次（`CreditsA/B/C`，各 150 帧 / 5 秒，仅替换名称参数）；
3. 通过 `ffmpeg concat -c copy` 直接拼接，**不重新编码**。

```bash
ffmpeg -f concat -safe 0 -i listA.txt -i mix.wav \
  -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k \
  -shortest -movflags +faststart out.mp4
```

拼接质量以 PSNR 验证：三个版本在 100 秒处**逐像素相同**（PSNR = inf），在 171 秒处 PSNR 为 24.1 dB，差异仅存在于落款文字，由此确认三版差异仅位于片尾。

## 10. 复盘：改进优先级

1. **为音频拼接增加单元测试**：读取后立即断言通道数、时长与首个发声点。该断言可避免整片返工。
2. **将「字幕不得重叠」设为时间轴的硬约束**，而非依赖人工抽查。TTS 句边界自带约 50 毫秒尾停顿，若不做夹紧处理，会出现两帧双字幕。
3. **尽早确定 CRF**。首版以 CRF 19 完成整片渲染后才发现暗部断层，只能重新渲染。
